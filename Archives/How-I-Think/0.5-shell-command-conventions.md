# 0.5 — Shell Command Conventions

## Purpose

This file records the user's normal command-line conventions so chats do not repeatedly misdiagnose or "correct" expected shell behavior.

Treat these mappings as the user's normal Fedora host workflow:

```text
grep → rg
cat  → bat
ls   → eza
vim  → nvim
```

## Standing Rule

When giving shell commands for the user's normal Fedora host:

- Assume these replacements are intentional and expected.
- Do not repeatedly explain that `grep` resolves to `rg`, `cat` to `bat`, `ls` to `eza`, or `vim` to `nvim`.
- Do not treat those mappings as errors or anomalies by themselves.
- Prefer commands that work naturally with the user's normal tools.
- Avoid making the user mentally translate basic commands while operating on autopilot or following a long command sequence.

## Exact-Semantics Exception

If exact GNU/coreutils behavior is required, use an explicit binary path rather than assuming the alias/function behavior is equivalent.

Examples:

```bash
/usr/bin/grep
/usr/bin/cat
/usr/bin/ls
```

Only do this when the exact command semantics actually matter.

## Toolbox / Container Exception

Toolbox and container environments may not have the same aliases, functions, packages, paths, or replacements as the host.

Inside Toolbox or another container:

- Do not assume the host mappings exist.
- Check or use explicit commands when the distinction matters.
- It is acceptable to call out the difference there because it can affect behavior.

## Assistant Behavior

The assistant should adapt commands before presenting them instead of repeatedly making the user fix common commands after the fact.

The intended default is:

```text
HOST
use the user's normal command environment

TOOLBOX / CONTAINER
verify when command resolution matters
```

Do not interrupt a technical workflow merely to explain a known command substitution unless that substitution is actually causing the current problem.
