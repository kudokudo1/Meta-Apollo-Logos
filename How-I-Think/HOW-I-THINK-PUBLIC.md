# How I Think

> **A public map of the recurring operations I use to understand, learn, communicate, remember, and act.**

This is a working model, not a diagnosis and not a claim that every mechanism here is unique to me.

Most of these operations are ordinary human operations. What may be more personal is their configuration: which ones I rely on most, how strongly they interact, what I preserve, and how often I move between them.

The map is allowed to be wrong.

> **Do not mistake the camera for the world.**

---

# Part I — Core Operators

## 1. Same Thing / Different Thing

The most basic operation is asking:

- What is the same?
- What is different?
- Under what predicate?
- At what time?
- From which camera?

Two things can be different in one way and the same in another.

Discord and Instagram are different companies, apps, and technical systems. They can still be the same thing under the predicate:

> **places where I talk to people**

Two sentences can use different words while carrying the same proposition.

A character can change appearance while remaining the same character.

A character can keep the same name and costume while changing enough important relationships that the identity no longer feels continuous.

The point is not to flatten difference.

The point is to locate it correctly.

---

## 2. Relations and Identity

Not every property lives entirely inside an object.

Some identities exist partly through relationships.

Examples:

- parent ↔ child
- teacher ↔ learner
- betrayal ↔ trust
- predecessor ↔ successor
- owner ↔ owned thing

A parent is not a parent in isolation.

A betrayal is not a betrayal without trust.

Sometimes changing the relation changes what the thing is in that context even when the object itself remains.

> **Sometimes the String is not inside either object. It is the relation between them.**

---

## 3. Identity Through Change

Identity is not always a screenshot.

It can be a trajectory.

```
X at one time
→ change
→ X at another time
```

The useful question is not only:

> Is this still X?

It is also:

> What changed, what remained, and which changes actually matter to the identity being tracked?

This lets continuity and transformation coexist.

---

## 4. Cameras and Lenses

Reality can remain the same while the view changes.

A camera can change:

- scale
- abstraction
- time
- observer
- definition
- causal direction
- discipline
- evidence standard
- comparison frame
- representation

Changing the camera does not automatically change the object.

A disagreement may disappear when two people finally use the same referent, scope, definitions, and lens.

If it survives that alignment, then the disagreement is more likely to be substantive.

> **Same channel. Same show. Then argue about the picture.**

---

# Part II — Building and Moving Information

## 5. Generator-Seeking

I often care less about memorizing outputs than finding the process that generates them.

```
observe behavior
→ infer generator
→ use generator to predict other behavior
→ test prediction
```

Once the generator is understood, many facts become cheaper to learn because they attach to the same parent structure.


### 5.1 Affordance-First Learning

Sometimes I understand what a thing **enables** before I know its formal vocabulary or conventional system.

The order can look like:

```
observe capability
→ recognize what it affords
→ connect it to a live problem
→ use it
→ learn the official details afterward
```

This can make learning look backwards from a conventional curriculum.

The capability enters the graph first.

The terminology catches up later.

---

## 6. Play It Out

Changing one variable is not enough.

Propagate the consequences.

Instead of:

> elf = human + pointy ears

ask:

> What happens if lifespan changes?  
> What does that do to memory?  
> History?  
> Grief?  
> Culture?  
> Politics?  
> Art?

A useful model should generate downstream effects.

This operation appears in worldbuilding, software, social reasoning, history, and hypothetical thought.

---

## 7. Analogy as Compression

Analogy is not only decoration.

A useful analogy can preserve:

- relationships
- constraints
- transformations
- expected behavior
- failure points

A mature analogy can be manipulated:

```
X + condition
X - property
X at another scale
X in another environment
```

If the relationships survive useful transformations, the analogy may be carrying real structure.

---

## 8. Cross-Domain Transfer

A useful relation can sometimes move between domains.

Examples:

- software ownership → institutional ownership
- lineage → historical continuity
- story inheritance → cultural transmission
- Git history → causal provenance

This does **not** mean the mechanisms are literally identical.

The question is whether the relevant structure transfers.

---

## 9. Generative Strings

Large models can compress into small handles.

A handle does not need to explicitly contain every detail.

It needs to preserve enough structure to regenerate what matters.

> **A String can contain a Web.**

The cycle often looks like:

```
expand
→ inspect structure
→ compress
→ carry forward
→ new information arrives
→ selectively expand
→ update
→ recompress
```

---

## 10. Return Pointers and Semantic Addresses

Small cues can reopen large contexts.

A pointer might be:

- a phrase
- a character
- an image
- a color
- a place
- a project name
- a visual position

A name like **Gohan**, **Spider-Man**, or **Shikamaru** can point to much more than the character itself.

It can mount an entire relational cluster.

The word is small.

The structure behind it is not.

# Part III — Learning, Attention, and Memory

## 11. Missing-Node Learning

Sometimes a large surrounding model already exists but one important concept is missing.

When that concept appears, older fragments can suddenly bind together.

```
large partial graph
+
missing concept
→
concept discovered
→
rapid integration
```

This can make learning look uneven.

A person can understand a large structure while still lacking standard vocabulary for one part of it.

---

## 12. Delayed Binding

Information does not always become useful when it is first received.

It may remain disconnected until another relationship appears years later.

Then:

> **WAIT A FUCKING SECOND.**

Old material can become newly meaningful without having been consciously active the entire time.


### 12.1 Wrong Before Right

Detecting an error and knowing the correction are separate operations.

Sometimes I can tell:

> **That relation is wrong.**

before I can say:

> **This is where it actually belongs.**

That unresolved state is useful information.

It can remain as a Ghost until the missing relationship becomes available.

---

## 13. Multiple Salience Indexes

The same underlying graph can be searched in different ways.

One index may prioritize:

- causality
- sequence
- ownership
- dependency
- provenance
- leverage

Another may prioritize:

- novelty
- emotion
- visual distinctiveness
- humor
- movement
- weirdness
- sensory hooks

I use **Shikamaru** and **Jinx** as compressed handles for these different traversal styles.

They are not literal brain modules.

> **Same graph. Different indexes. One hand.**

---

## 14. Persistent Graph / Serial Output

Many branches can remain relevant while only one action can happen at a time.

Speech is serial.

Typing is serial.

Clicking is serial.

Listening is serial.

That does not mean the underlying representation is equally serial.

> **Serial output does not imply serial representation.**

A conversation transcript is therefore not the thought itself.

It is a serialization of part of a larger graph.

---

## 15. Graph Globally, Serialize Locally

Work often exists as families rather than one perfect master list.

For example:

```
Forest
Hospital
Meta Apollo
Post-Apollo
Git
CRT
```

There may be strong local order inside each family without one natural total order across all of them.

> **Graph globally. Serialize locally where causality or collision requires it.**

---

## 16. Memory, Continuity, and Provenance

Continuity does not require keeping everything active.

It requires being able to reconstruct the right state.

A useful distinction:

- **Hot** — active now
- **Warm** — quickly recoverable
- **Cold** — preserved but not currently loaded

History matters because it preserves:

- why a decision existed
- which assumption was active
- what failed
- what changed
- what caused the current state

> **History is cached future computation.**

Corrections should preserve enough provenance to explain how the model changed.


### 16.1 The Route Can Survive Before the Explanation

Under fatigue, overload, or heavy compression, precise vocabulary and full explanation can degrade before useful navigation does.

I may lose the canonical words while still being able to:

- return to the correct object
- reopen the right context
- continue the relevant task
- recognize what matters
- follow a familiar route

So:

> **losing the words is not always the same as losing the model.**

A compressed relational or sensory address can remain usable even when full semantic decompression is expensive.

# Part IV — Uncertainty and Action

## 17. Ghosts

A **Ghost** is an unresolved mismatch.

It may be:

- a contradiction
- a missing relation
- a stale assumption
- a wrong predicate
- incomplete information
- version mismatch
- hidden useful capability
- noise

Useful states:

**GHOST**  
Something may be here.

**OBSERVED**  
We can point to it happening.

**MODEL**  
This is the current explanation.

**MECHANISM**  
We know how it works.

Not every Ghost deserves immediate resolution.

---

## 18. Action as Sensor

Action is not only execution.

It can produce information.

```
model
→ intervene
→ observe response
→ infer hidden structure
→ update model
```

Reality can answer questions that thought alone cannot settle.

---

## 19. Minimum Sufficient Understanding

Do not understand the entire universe before acting.

Understand enough for the next bounded, informative move.

---

## 20. Minimum Sufficient Commitment

Do not wager the whole system just to learn whether a path is viable.

Prefer:

- branches
- rollback
- adapters
- staged migration
- reversible changes
- probes
- experiments

A useful rule is:

> **Act strongly while preserving a return path.**

The environment can carry state.

Examples:

- papers on a floor
- multiple screens
- tabs
- files

Position, color, shape, and history can become retrieval cues.

The environment is not merely storage.

It can become part of the working system.

## 22. AI Complementarity

AI is useful to me because it attacks several recurring bottlenecks:

- missing vocabulary
- alternate representations
- serialization
- candidate generation
- implementation
- retrieval
- decompression
- rapid prototyping

I supply different things:

- persistent context
- selection pressure
- taste
- relationship checking
- cross-domain bridges
- problem ownership
- rejection

The useful loop is:

```
internal model
→ AI renders candidate
→ inspect
→ reject / keep / modify
→ implement
→ reality responds
→ update
```

AI is not simply an answer machine in this workflow.

It is part of an iterative model-building loop.

## 23. Forest / Post-Apollo / Hospital

These projects are not treated as literal diagrams of my mind.

They are external systems created under related information pressures.

A useful compression:

**Forest**  
How can large persistent knowledge remain usable without loading everything at once?

**Post-Apollo**  
How can large changing computational state remain understandable and controllable to one human?

**Hospital**  
How can a project preserve continuity while individual workers are replaceable?

A compact summary:

> **Forest = distribution**  
> **Post-Apollo = navigation**  
> **Hospital = continuity**

They are applications and behavioral evidence, not the core theory itself.

# Part VI — Human Expression

## 24. Communication

Communication is not successful merely because the words are grammatical.

Both sides may need to align:

- referent
- scope
- definitions
- scale
- relevant relationships
- camera

Two sentences can look different while expressing the same proposition.

Two sentences can look similar while changing an important relationship.

The goal is not identical wording.

The goal is preserving the intended structure.

### 25.1 Artifacts as Autobiographical Landmarks

Personally meaningful artifacts can act as retrieval keys.

An old drawing, notebook, object, arrangement, or project may reopen much more than the object itself:

```
artifact
→ recognition
→ place / time
→ why it was made
→ surrounding interests
→ related people or projects
→ larger autobiographical context
```

This is one reason art and physical space can function as more than storage.

They can preserve **addresses back into prior states of self**.

The claim is not that the recovered memory is perfectly complete or perfectly accurate.

The useful observation is that small external cues can trigger large relational reconstruction.

---

## 26. Stories, Characters, and Modern Myth

Stories can carry relational models before the reader has formal vocabulary for them.

Examples:

- Spider-Man → power / responsibility
- Superman → power / restraint / service
- Dragon Ball → growth / teaching / inheritance
- myth and fairy tale → compressed social and moral structure

A character can become a semantic address for a much larger model.

The useful distinction is:

**different carrier / same generator**  
Identity may survive.

**same carrier / different generator**  
Identity may not survive.

This is why continuity, retcons, succession, and inherited meaning can matter deeply even in things dismissed as "kids' shows."

# Part VII — Limits and Evidence

## 27. Failure Modes

This model has costs.

Possible failure modes include:

- serialization bottlenecks
- over-connection
- false pattern matches
- compression loss
- reconciliation overload
- stale branches
- switching cameras when a contradiction should simply be admitted

A model that only explains strengths is not useful.

---

## 28. Evidence Discipline

Useful labels:

- **USER-STATED**
- **OBSERVED**
- **INFERRED**
- **METAPHOR**
- **PROVISIONAL**
- **CORRECTED**

Evidence is stronger when it includes:

1. prediction before confirmation
2. external artifacts
3. behavior observed before naming
4. perturbation or testing
5. historical material predating the theory
6. cross-domain recurrence
7. repeated self-report
8. AI agreement

Repeated agreement is not automatically independent evidence.

Ten AIs trained on similar material are not ten independent witnesses.

A theory must be allowed to lose.

> **Do not prove the model by making everything fit.**

# The Three-Layer Structure

This public document is the top layer.

## Layer 1 — Map

> **Here is the current model.**

Readable, compressed, forward-facing.

## Layer 2 — Evidence

> **Here are selected examples that support, challenge, or clarify individual claims.**

Conversation excerpts, old artifacts, project behavior, predictions, corrections, and other clean proof stories belong here.

## Layer 3 — Archive

> **Here is the full provenance.**

The long conversations, older models, abandoned explanations, giant evidence chains, technical histories, and raw material remain available when reconstruction is necessary.

In short:

> **Map → Evidence → Archaeology**

You should not need to read the whole archive to understand the model.

The archive exists so the model can be checked, corrected, and reconstructed when necessary.
